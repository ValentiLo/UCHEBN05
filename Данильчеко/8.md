## Как сохранить результат на GitHub без риска утечки секретов

Поскольку у вас уже обнаружена утечка Slack Webhook URL, вот **безопасный способ сохранить код** (без документа .docx с секретами):

---

## ШАГ 1: Удалите секреты из вашего локального проекта

### Создайте безопасную структуру файлов:

```bash
# 1. Создайте .gitignore (если ещё нет)
cat > .gitignore << 'EOF'
# Секреты и конфиги
.env
.env.*
*.key
*.pem
secrets.*
config.local.*
*.docx
*.xlsx

# Логи
*.log
logs/
generated_scripts/*.log

# Временные файлы
__pycache__/
*.pyc
.DS_Store
*.tmp

# Документы с секретами
Данильчеко/
*.docx
*.pdf
EOF
```

### 2. Создайте файл `.env.example` (без реальных секретов)

```bash
cat > .env.example << 'EOF'
# Telegram (получите свои токены)
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here
TELEGRAM_CHAT_ID=your_chat_id_here

# Slack (создайте свой вебхук)
SLACK_WEBHOOK_URL=https://hooks.slack.com/services/YOUR/TEAM/HOOK
SLACK_BOT_TOKEN=xoxb-your_bot_token
SLACK_CHANNEL=#deployments

# ELK Stack
LOGSTASH_HOST=localhost
LOGSTASH_PORT=5000
ELASTICSEARCH_HOST=localhost:9200

# Prometheus
PROMETHEUS_HOST=localhost
PROMETHEUS_PORT=9090
EOF
```

### 3. Удалите скомпрометированный файл

```bash
# Удалите из текущей директории
rm -f "Данильчеко/7.docx"
rm -rf "Данильчеко/"

# Или если файл в другом месте
find . -name "*.docx" -type f -delete
```

---

## ШАГ 2: Сохраните только код (без истории с секретами)

### Создайте новый чистый репозиторий

```bash
# 1. Создайте новую папку для чистого кода
mkdir clean_deploy_system
cd clean_deploy_system

# 2. Скопируйте только нужные файлы (игнорируя секреты)
cp ../deploy_system/config.yaml .
cp ../deploy_system/template.sh.j2 .
cp ../deploy_system/template.ps1.j2 .
cp ../deploy_system/generator.py .
cp ../deploy_system/deployer.py .
cp ../deploy_system/main.py .
cp ../deploy_system/web_app.py .
cp ../deploy_system/metrics.py .
cp ../deploy_system/slack_notifier.py .
cp ../deploy_system/telegram_notifier.py .
cp ../deploy_system/test_system.py .
cp ../deploy_system/requirements.txt .
cp ../deploy_system/Dockerfile .
cp ../deploy_system/docker-compose.yml .
cp ../deploy_system/docker-compose.monitoring.yml .
cp -r ../deploy_system/templates/ .
cp -r ../deploy_system/elk_stack/ .
```

### 4. Создайте README.md с инструкцией

```bash
cat > README.md << 'EOF'
# Система автоматического развертывания ПО

## Описание
Система для генерации серверных скриптов и автоматического развертывания ПО на удаленных рабочих станциях.

## Функционал
- Генерация bash/PowerShell скриптов из шаблонов
- Автоматический деплой через SSH
- Веб-интерфейс на Flask
- Мониторинг (Prometheus + Grafana)
- Централизованное логирование (ELK Stack)
- Уведомления (Telegram + Slack)

## Быстрый старт

### 1. Клонирование репозитория
```bash
git clone https://github.com/your-username/deploy-system.git
cd deploy-system
```

### 2. Настройка окружения
```bash
cp .env.example .env
# Отредактируйте .env, добавив свои токены
```

### 3. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 4. Запуск
```bash
python web_app.py
```

### 5. Запуск с Docker
```bash
./start_all.sh
```

## Переменные окружения
Создайте файл `.env` со следующими переменными:
- `TELEGRAM_BOT_TOKEN` - токен Telegram бота
- `TELEGRAM_CHAT_ID` - ID чата
- `SLACK_WEBHOOK_URL` - URL вебхука Slack
- и другие (см. `.env.example`)

## Лицензия
MIT
EOF
```

## ШАГ 3: Инициализируйте чистый репозиторий

```bash
# Инициализируйте Git
git init

# Добавьте все файлы
git add .

# Проверьте, что нет секретов
git grep -i "hooks.slack.com"  # должно быть пусто
git grep -i "TELEGRAM_BOT_TOKEN"  # только в .env.example

# Сделайте первый коммит
git commit -m "Initial commit: Deploy system without secrets"

# Добавьте remote (НОВЫЙ чистый репозиторий!)
git remote add origin https://github.com/ВАШ_ЛОГИН/deploy-system.git

# Отправьте на GitHub
git push -u origin main
```

## ШАГ 4: Что делать со старым репозиторием

### Вариант А: Удалить старый репозиторий

1. Перейдите на GitHub
2. Settings → Danger Zone → Delete this repository
3. Создайте новый чистый репозиторий

### Вариант Б: Очистить историю

```bash
# Сделайте бэкап перед очисткой
git clone https://github.com/ДАНИЛЬЧЕКО/репозиторий.git backup

# Очистите историю от секретов
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch 'Данильчеко/7.docx'" \
  --prune-empty --tag-name-filter cat -- --all

# Удалите все .docx файлы из истории
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch '*.docx'" \
  --prune-empty --tag-name-filter cat -- --all

# Force push
git push origin --force --all
git push origin --force --tags
```

## ШАГ 5: Настройте защиту от повторения

### GitHub Actions секреты

1. Перейдите в Settings → Secrets and variables → Actions
2. Добавьте секреты:
   - `SLACK_WEBHOOK_URL`
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`

### Pre-commit хуки

```bash
pip install pre-commit

cat > .pre-commit-config.yaml << 'EOF'
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.4.0
    hooks:
      - id: detect-private-key
      - id: check-added-large-files
  - repo: https://github.com/Yelp/detect-secrets
    rev: v1.4.0
    hooks:
      - id: detect-secrets
        args: ['--baseline', '.secrets.baseline']
  - repo: https://github.com/zricethezav/gitleaks
    rev: v8.18.0
    hooks:
      - id: gitleaks
EOF

pre-commit install
```

## КОМАНДЫ ДЛЯ БЫСТРОГО СОХРАНЕНИЯ

```bash
# 1. Очистите секреты
rm -f "Данильчеко/7.docx"
git rm --cached "Данильчеко/7.docx" 2>/dev/null

# 2. Создайте .gitignore
cat > .gitignore << 'EOF'
.env
*.docx
*.log
__pycache__/
EOF

# 3. Создайте .env.example
cp .env .env.example 2>/dev/null || echo "# Copy this to .env" > .env.example
sed -i 's/your_actual_token/your_token_here/g' .env.example

# 4. Коммит без секретов
git add .
git commit -m "Remove secrets, add .env.example"

# 5. Push
git push origin main --force
```
