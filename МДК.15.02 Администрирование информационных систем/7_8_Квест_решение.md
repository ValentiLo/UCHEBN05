# Решение квеста «Пять ключей к мастерству планирования»

## 🗝️ Ключ 1: «Щит предвидения»

### Решение испытания «Диск-предсказатель»

**1. Расчёт дней до заполнения диска:**
- Свободно: 30%
- Заполняется: 2% в день
- До полного заполнения: 30% / 2% в день = **15 дней**

**2. Регламентные работы для предотвращения проблемы:**

| День | Действие | Цель |
|------|----------|------|
| **Сейчас** | Анализ логов: что занимает место | Найти источник роста |
| **День 1** | Очистка временных файлов, кэшей | Освободить 5-10% |
| **День 2** | Архивация старых логов (старше 3 месяцев) | Освободить 3-7% |
| **День 3** | Настройка автоматического оповещения при заполнении >70% | Раннее предупреждение |
| **День 5** | Проверка пользовательских квот | Кто использует больше всего? |
| **День 7** | Очистка корзины и ненужных бекапов | Освободить 2-5% |
| **День 10** | Планирование расширения дискового пространства | Долгосрочное решение |

**3. План на две недели:**
```
Неделя 1:
- Пн: Анализ + очистка временных файлов
- Вт: Архивация логов
- Ср: Настройка мониторинга
- Чт: Аудит квот пользователей
- Пт: Отчёт + планирование

Неделя 2:
- Пн: Переговоры о расширении диска
- Вт: Заказ оборудования
- Ср-Чт: Подготовка к расширению
- Пт: Резервное копирование перед изменениями
```

**Ключевой вывод:** Проблему можно было предвидеть за месяц, если бы мониторинг был настроен заранее.

## 🗝️ Ключ 2: «Часы эффективности»

### Решение испытания «Битва за ресурсы»

**Матрица Эйзенхауэра:**
1. **Срочно и важно:** Закрытие квартала (бухгалтерия)
2. **Важно, но не срочно:** Обновление CRM (отдел продаж)
3. **Срочно, но не важно:** Тестирование (разработчики) — можно делегировать

**Календарь работ на неделю:**

| День | Утро (9:00-13:00) | День (14:00-18:00) | Вечер (19:00-22:00) |
|------|-------------------|-------------------|-------------------|
| **Пн** | Бухгалтерия: настройка сервера | Бухгалтерия: тестовый прогон | Мониторинг процесса |
| **Вт** | Бухгалтерия: основная обработка | Бухгалтерия: продолжение | Резервное копирование |
| **Ср** | Бухгалтерия: финализация | Обновление CRM: подготовка | CRM: начало обновления |
| **Чт** | CRM: завершение обновления | Тестирование: настройка среды | Тестирование: автотесты |
| **Пт** | Тестирование: ручные проверки | Документация + отчёты | Планирование след. недели |

**Объяснение отделам:**

**Бухгалтерии:** «Ваша задача критична для компании. Выделяем первые 3 дня недели, когда система наименее загружена другими процессами.»

**Отделу продаж:** «CRM обновим сразу после бухгалтерии, чтобы новая система заработала к началу активных продаж в конце недели.»

**Разработчикам:** «Тестирование запустим в автоматическом режиме в нерабочее время, результаты будут к утру пятницы.»

**Оптимизация:** Стажёр помогает с подготовкой тестовой среды и документацией.

## 🗝️ Ключ 3: «Амулет непрерывности»

### Решение испытания «Обновление без остановки»

**Поэтапный план обновления:**

**1. Подготовка (за 3 дня до):**
- Уведомление пользователей: «23 января с 02:00 до 06:00 — плановые работы. Система будет доступна в режиме чтения»
- Резервное копирование: полный бэкап + бэкап конфигураций
- Тестирование обновления на тестовом стенде

**2. Стратегия обновления:**
```
Серверная инфраструктура:
Основной сервер → Резервный сервер → Возврат трафика

Шаги:
1. 02:00 - Переключение нагрузки на резервный сервер
2. 02:15 - Обновление основного сервера
3. 03:30 - Тестирование обновления (15 минут)
4. 04:00 - Переключение нагрузки обратно
5. 04:15 - Обновление резервного сервера
6. 05:00 - Синхронизация данных
7. 05:30 - Финальное тестирование
8. 06:00 - Работа возобновлена
```

**3. План отката:**
- Если обновление не удалось за 1 час → откат на бэкап
- Автоматическое оповещение ответственных при проблемах
- Готовый скрипт восстановления

**4. Окно обслуживания:**
- **Лучшее время:** 02:00-06:00 (минимальная активность)
- **Резервное окно:** следующая суббота, если что-то пойдёт не так

```

     ┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
Почта│███│███│███│███│███│   │   │   │   │   │
Резер│   │   │███│███│███│   │   │   │   │   │
Обуч │   │   │   │   │   │███│███│   │   │   │
Аудит│   │   │   │   │   │###│   │   │   │   │
Буфер│   │   │   │   │   │   │   │░░░│░░░│░░░│
     └───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
```

**Критический путь:** Почта (5 дней) → Аудит (1 день) → Обучение (2 дня)

**Распределение задач:**

**Дни 1-2 (частичная занятость):**
- Почта: подготовка, документация (стажёр помогает)
- Резервное копирование: исследование решений

**Дни 3-5:**
- Почта: активная миграция
- Резервное копирование: настройка параллельно

**День 6 (аудит):**
- Обучение: подготовка материалов (можно делать параллельно с аудитом)

**Дни 7-8:**
- Обучение сотрудников

**Дни 9-10 (буфер):**
- Доработки, исправление замечаний аудита
- Документирование завершённых проектов

## 🗝️ Ключ 5: «Сумка готовности»

### Решение испытания «Чёрный вторник»

**Чек-лист действий при ЧП:**

**Первые 15 минут:**
1. [ ] Оповестить руководство: «Происходит инцидент, оцениваем масштаб»
2. [ ] Запустить план восстановления электропитания (альтернативные схемы)
3. [ ] Переключить критичные системы на аварийный хостинг (если предусмотрено)

**Час 1:**
1. [ ] Определить RTO (время восстановления) для каждой системы
2. [ ] Бухгалтерия: организовать временную работу на ноутбуках с локальными копиями
3. [ ] Важные клиенты: отправить статус «знаем о проблеме, работаем»

**Час 2-4:**
1. [ ] Восстановить интернет через мобильные 4G-модемы для критичных служб
2. [ ] Запустить генератор в ручном режиме (вызвать сервис)
3. [ ] Подготовить отчёт для руководства с ETA восстановления

**Регламентные работы, которые предотвратили бы худшее:**
- Регулярное тестирование генератора (раз в месяц)
- Наличие офлайн-копий критичных данных
- Обучение сотрудников работе в аварийном режиме
- Договорённости с соседними офисами о временном размещении

**Уроки на будущее:**
1. Добавить второй независимый источник интернета
2. Регулярные учения по восстановлению
3. Автоматические SMS-оповещения при сбоях
4. Создать «аварийные чемоданы» с оборудованием в разных местах

## 🏆 Финальное решение: «Архитектор систем»

### Единый план администрирования «ТехноГигант»

**1. Годовой календарь регламентных работ:**

```
Январь:   Аудит безопасности, планирование года
Февраль:  Обновление инфраструктуры
Март:     Подготовка к квартальному отчёту
Апрель:   Резервное копирование + тестовое восстановление
Май:      Обучение сотрудников, обновление ПО
Июнь:     Полугодовой аудит, чистка архивов
Июль:     Профилактика оборудования
Август:   Обновление систем перед осенним сезоном
Сентябрь: Подготовка к пиковой нагрузке
Октябрь:  Аудит перед годовым отчётом
Ноябрь:   Резервные копии + восстановление (учения)
Декабрь:  Итоги года, планирование следующего
```

**2. Матрица ответственности RACI:**

| Задача                  | Админ | Стажёр | Руководство | Пользователи |
|-------------------------|-------|---------|-------------|--------------|
| Ежедневный мониторинг   | R/A   | I       | C           | I            |
| Резервное копирование   | R     | A       | I           | I            |
| Обновление ПО           | R/A   | I       | C           | I            |
| Обучение                | R     | A       | C           | R (участие)  |
| Аудит безопасности      | R     | I       | A/C         | I            |

**3. Библиотека шаблонов:**
- Шаблон плана обновления
- Шаблон уведомления пользователей
- Шаблон отчёта об инцидентах
- Шаблон регламентных работ
- Чек-листы для типовых операций

**4. Система эскалации проблем:**
```
Уровень 1: Стажёр → решает сам (30 мин)
Уровень 2: Админ → привлекает специалиста (2 часа)
Уровень 3: Руководство → внешние эксперты (4 часа)

```

**5. Регулярные аудиты эффективности:**
- Ежеквартальный review планов
- Анализ выполненных/просроченных задач
- Опрос пользователей об удовлетворённости
- Бенчмаркинг с лучшими практиками отрасли
- Непрерывное улучшение на основе метрик

## 🎯 Итоговый артефакт: «Автоматический планировщик»

**Функциональность:**
1. **Интеллектуальное планирование:** Анализирует исторические данные, предлагает оптимальные окна для работ
2. **Автоматические уведомления:** Отправляет напоминания пользователям и ответственным
3. **Адаптивные графики:** Перестраивает планы при изменении условий
4. **Аналитика эффективности:** Показывает, какие планы работают лучше всего
5. **Обучение новых сотрудников:** Пошаговые гайды для каждой процедуры

**Пример правила:**  
«Если свободное место на диске <20% и падает на >1% в день → автоматически планировать очистку в ближайшее окно обслуживания + уведомить администратора»
