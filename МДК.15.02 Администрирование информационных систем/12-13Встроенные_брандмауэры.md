### Встроенные брандмауэры операционных систем

Брандмауэр — это первый рубеж защиты сети, фильтрующий входящий и исходящий трафик на основе заданных правил. Подходы к его настройке в Windows и Linux кардинально отличаются.

#### **Брандмауэр в ОС Windows**

В современных версиях Windows используется **Брандмауэр Защитника Windows**. Это мощный, управляемый через графический интерфейс инструмент . Он позволяет настраивать правила для входящих и исходящих подключений, создавать исключения для программ и портов. Для быстрого доступа к настройкам можно использовать команду `wf.msc`, которая открывает оснастку "Брандмауэр Защитника Windows в режиме повышенной безопасности", где доступны гибкие настройки для профилей "Доменный", "Частный" и "Гостевой/Общедоступный".

#### **Брандмауэр в ОС Linux**

В Linux ситуация сложнее: брандмауэр не является единой программой, а представляет собой набор механизмов фильтрации внутри ядра (`netfilter`) и утилит для управления ими . Основные инструменты:
*   **`iptables`**: Классический интерфейс управления правилами для механизма `netfilter`. Позволяет создавать сложные цепочки правил для фильтрации пакетов, трансляции адресов (NAT) и модификации пакетов . Настройки сохраняются в файлах, например, `/etc/iptables/rules.v4` в Ubuntu или `/etc/sysconfig/iptables` в CentOS .
*   **`nftables`**: Современная замена `iptables`, объединяющая функционал нескольких утилит и предлагающая более простой синтаксис. Она управляется командой `nft` .
*   **Надстройки для упрощения (`UFW`, `firewalld`)**: Для упрощения работы с `iptables` созданы высокоуровневые инструменты. **`UFW` (Uncomplicated Firewall)** — стандартная надстройка в Ubuntu, позволяющая управлять правилами простыми командами, например, `ufw allow ssh` или `ufw deny http` . **`firewalld`** используется в CentOS/RHEL/Fedora и оперирует понятиями "зон" и "сервисов", что удобно для управления политиками в динамической среде .

Сравнение брандмауэров Windows и Linux представлено в таблице ниже.

**Таблица 1: Сравнение встроенных брандмауэров Windows и Linux**

| Характеристика | Брандмауэр Защитника Windows (Windows) | Netfilter/iptables/nftables (Linux) |
| :--- | :--- | :--- |
| **Основной интерфейс** | Графическая оснастка (`wf.msc`), PowerShell | Командная строка (`iptables`, `nft`, `ufw`), конфигурационные файлы |
| **Уровень гибкости** | Высокий, удобен для управления правилами для приложений и портов в доменной/корпоративной среде  | Экстремально высокий, позволяет управлять практически любым аспектом сетевого трафика, включая создание сложных маршрутизаторов и шлюзов  |
| **Типичный вариант использования** | Защита рабочей станции или сервера в корпоративной сети, настройка через групповые политики | Серверы, межсетевые экраны, маршрутизаторы, встроенные системы, где требуется максимальный контроль |

### Пользователи и группы в операционных системах

Управление пользователями и группами — основа для организации коллективной работы и разграничения доступа.

#### **Пользователи и группы в Windows**

Управление локальными пользователями и группами осуществляется через оснастку **"Управление компьютером"** (Computer Management) -> **"Локальные пользователи и группы"** (`lusrmgr.msc`) . В ней можно создавать, удалять и блокировать пользователей, задавать пароли и управлять членством в группах. Для централизованного управления в домене используется оснастка **"Active Directory — пользователи и компьютеры"**, где учетные записи хранятся в базе данных Active Directory .

Ключевые идентификаторы безопасности — **SID (Security Identifier)** — уникальные идентификаторы, присваиваемые каждому пользователю и группе при создании .

#### **Пользователи и группы в Linux**

В Linux управление пользователями и группами ведется преимущественно из командной строки. Учетные записи хранятся в файле `/etc/passwd`, а их пароли (в зашифрованном виде) — в `/etc/shadow`. Информация о группах хранится в файле `/etc/group`, а пароли групп и список администраторов групп — в `/etc/gshadow` .

Для управления используются команды: `useradd`, `usermod`, `userdel` (для пользователей) и `groupadd`, `groupmod`, `groupdel` (для групп). Управление членством в группе выполняется командами `gpasswd` (например, `gpasswd -a username groupname` для добавления пользователя) или `usermod -aG` . Каждому пользователю и группе присваиваются числовые идентификаторы: **UID (User ID)** и **GID (Group ID)** .

Сравнение систем управления пользователями и группами представлено ниже.

**Таблица 2: Сравнение систем пользователей и групп в Windows и Linux**

| Характеристика | Windows | Linux |
| :--- | :--- | :--- |
| **Основные инструменты** | Графические оснастки (`lusrmgr.msc`, ADUC), PowerShell | Командная строка (`useradd`, `groupadd`, `gpasswd`), текстовые файлы |
| **Хранение данных** | База данных SAM (Security Accounts Manager) или Active Directory | Текстовые файлы (`/etc/passwd`, `/etc/shadow`, `/etc/group`, `/etc/gshadow`)  |
| **Идентификаторы** | SID (Security Identifier)  | UID (User ID), GID (Group ID)  |
| **Особенности** | Два типа групп: локальные (для одной машины) и доменные (для всего домена). SID пользователей и групп находятся в одном пространстве имен. | Группы используются для назначения прав доступа к файлам. UID и GID — это непересекающиеся множества . |

### Системы пользовательских прав в Windows и Linux

Системы прав доступа — это механизмы, определяющие, какие операции (чтение, запись, выполнение) конкретный пользователь или группа может выполнять над объектом (файлом, папкой и т.д.).

#### **Система прав в Windows**

Windows использует более сложную, **дискреционную модель управления доступом** . Каждый объект (файл, папка, раздел реестра, принтер) имеет **дескриптор безопасности**. Он содержит:
*   **Список контроля доступа (DACL)**: список, состоящий из записей (ACE), каждая из которых разрешает или запрещает определенные действия для конкретного пользователя или группы .
*   **Права доступа** в Windows делятся на :
    *   **Специальные права**: зависят от типа объекта (например, для файлов это "Чтение данных", "Запись данных", "Выполнение файла", "Удаление подпапок и файлов").
    *   **Стандартные права**: общие для всех объектов ("Удаление", "Чтение разрешений", "Смена владельца").
    *   **Родовые права**: логические наборы специальных и стандартных прав, упрощающие администрирование (например, "Чтение", "Запись", "Изменение", "Полный доступ").

Важной особенностью является **наследование прав** — дочерние объекты по умолчанию наследуют права от родительского контейнера, что упрощает управление . Запрещающие правила имеют приоритет над разрешающими, за исключением коллизий наследования .

#### **Система прав в Linux (модель UGO/UID)**

В Linux используется более простая, но элегантная модель **UGO (User-Group-Others)** . Для каждого файла и каталога определены три категории субъектов:
1.  **Владелец (User)**.
2.  **Группа-владелец (Group)**.
3.  **Остальные пользователи (Others)**.

Для каждой категории задаются три базовых права :
*   **r (read)** — чтение. Для каталога — просмотр списка файлов.
*   **w (write)** — запись. Для каталога — создание и удаление файлов в нем (при наличии права на выполнение).
*   **x (execute)** — выполнение. Для каталога — возможность войти в него (`cd`) и получить доступ к файлам.

Права хранятся в индексе (inode) файла . Алгоритм проверки работает строго по порядку :
1.  Если пользователь — владелец, применяются права для владельца. Проверка завершается.
2.  Если пользователь входит в группу-владельца, применяются права для группы.
3.  В остальных случаях применяются права для остальных.

Из-за ограниченности базовой модели существуют дополнительные биты: **SUID**, **SGID**, **Sticky bit** . SUID позволяет выполнить файл с правами его владельца (как в примере с `passwd`). Sticky bit для каталога (например, `/tmp`) запрещает пользователям удалять чужие файлы.

Для более тонкого разграничения прав в Linux используются **ACL (Access Control Lists)** — расширение, позволяющее задавать права для произвольных пользователей и групп, как в Windows .

Сравнение систем прав представлено в таблице.

**Таблица 3: Сравнение систем пользовательских прав Windows и Linux**

| Характеристика | Windows (DACL) | Linux (UGO/ACL) |
| :--- | :--- | :--- |
| **Модель** | Дискреционная (списки контроля доступа — ACL)  | Базовая: UGO (User-Group-Others). Расширенная: ACL  |
| **Гибкость** | Высокая. Можно назначить индивидуальные права любому пользователю или группе через ACL  | Базовая модель ограничена. Для индивидуальных прав или прав для нескольких групп необходимо использовать ACL |
| **Права доступа** | Множество специальных прав (до 14 типов для файлов) и стандартных прав  | Три базовых права (rwx)  |
| **Механизм работы** | Дескриптор безопасности, содержащий DACL. Проверка прав идет по списку ACE | Проверка по иерархическому алгоритму (владелец -> группа -> остальные)  |
| **Наследование прав** | Поддерживается и является ключевым механизмом  | Требует явного наследования через ACL или настройки |

### Заключение

Подводя итог, можно сказать, что подходы Microsoft Windows и Linux к ключевым аспектам безопасности и управления являются отражением их философии: Windows стремится к централизованному, удобному управлению и интеграции, в то время как Linux предлагает гибкость, прозрачность и мощь командной строки.

Windows предлагает интегрированные, удобные для администратора инструменты с графическим интерфейсом, что упрощает настройку брандмауэра, управление пользователями и назначение детальных прав доступа. Ее система прав (DACL) является более сложной и гибкой "из коробки".

Linux, напротив, требует от администратора знаний командной строки и понимания текстовых конфигураций, но предоставляет за это непревзойденный контроль над системой. Его брандмауэр (`netfilter`) — это индустриальный стандарт для построения высокопроизводительных сетевых решений. Система прав UGO проста и надежна, а для сложных случаев всегда доступны ACL .

Выбор между этими подходами часто диктуется конкретными задачами инфраструктуры: для корпоративной среды с доменом Active Directory выбор Windows Server очевиден, в то время как для веб-сервера или высоконагруженного шлюза Linux будет более гибким и производительным решением.
