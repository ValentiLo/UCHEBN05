# Практическое задание: Создание матрицы RACI для ИТ-отдела

## 📋 **Ситуация**
Вы — системный администратор в компании "ТехноПлюс" (50 сотрудников). Нужно спланировать **миграцию почтового сервера** с устаревшей системы на Microsoft 365.

### **Команда проекта:**
1. **Вы (ИТ-админ)** — основной исполнитель
2. **Сетевой инженер** — отвечает за сетевую инфраструктуру
3. **Руководитель ИТ-отдела** — ваш начальник
4. **Финансовый директор** — утверждает бюджет
5. **Секретарь директора** — тестовый пользователь
6. **Все сотрудники** — конечные пользователи

## 💡 **Подсказки для размышления:**

**Для задачи 1 (Составление бюджета):**
- Кто собирает цифры? (R)
- Кто утверждает бюджет? (A) 
- С кем советуются по статьям расходов? (C)
- Кого просто информируют? (I)

**Для задачи 3 (Настройка DNS):**
- Кто технически выполняет изменения? (R)
- Кто отвечает, что настройки верны? (A)
- Кто должен знать о времени изменения? (C/I)

**Для задачи 6 (Тестирование):**
- Кто выполняет тесты? (R)
- Кто утверждает, что всё работает? (A)
- Кто является тестовым пользователем? (C или R?)

## 🛠️ **Задание 2: Анализ проблемных ситуаций**

**Ситуация А:** После миграции у бухгалтерии не приходят важные письма от банка. Все указывают друг на друга:
- Вы говорите: "Я перенёс данные, DNS настраивал сетевой"
- Сетевой говорит: "Я сделал всё по инструкции админа"
- Руководитель: "Кто за это отвечает?"

**Вопрос:** Какая ошибка в матрице RACI привела к этой ситуации?

**Ситуация Б:** При обучении сотрудников возникла путаница:
- Вы проводите обучение
- Секретарь тоже проводит своё обучение
- Сотрудники получают противоречивые инструкции

**Вопрос:** Как правильно распределить RACI для обучения?

## 📊 **Задание 3: Создайте свою матрицу**

Придумайте **регламентную задачу** из вашего опыта (или возьмите из квеста: "Резервное копирование") и создайте для неё матрицу RACI.

**Пример структуры:**

```
Процесс: [Название процесса, например "Еженедельное резервное копирование"]

Роли:
1. Старший администратор
2. Младший администратор  
3. Руководитель отдела
4. Ответственный за безопасность
5. Пользователи критических систем

Задачи:
1. Подготовка носителей
2. Запуск копирования
3. Проверка целостности
4. Отчёт об успешности
5. Реакция на сбои

Матрица RACI:
[Заполните таблицу]
```

---

## ✅ **Критерии правильности решения:**

1. **На каждую задачу — только один A** (подотчётный)
2. **Хотя бы один R** (исполнитель) на задачу
3. **Не должно быть пустых строк** (у каждой задачи кто-то отвечает)
4. **Логичное распределение** (технические задачи — у технических специалистов, финансовые — у финансистов)
5. **Учёт компетенций** (не назначать R тому, кто не умеет выполнять задачу)

---

## 🧩 **Пример правильного заполнения (для одной задачи):**

**Задача:** "Настройка DNS-записей"

| Роль | Буква | Обоснование |
|------|-------|-------------|
| **ИТ-админ** | **R** | Технически выполняет настройку |
| **Сетевой инженер** | **A** | Отвечает за корректность сетевых настроек |
| **Руководитель ИТ** | **C** | Согласовывает время изменений (чтобы не в рабочее время) |
| **Фин. директор** | **I** | Информируется, что технические работы идут по плану |
| **Секретарь** | **I** | Знает, когда возможны перебои с почтой |
| **Все сотрудники** | **I** | Получают уведомление о технических работах |

---

## 💎 **Что это даёт на практике?**

1. **Перед началом работ:** Распечатали матрицу — все знают свои роли
2. **При возникновении проблемы:** Смотрим матрицу — сразу видно, к кому идти
3. **При сдаче работы:** Знаем, кто должен поставить подпись (A)
4. **При планировании:** Видим нагрузку на каждого участника

**Реальная выгода:** На проекте из 10 задач экономия 5-7 часов на согласованиях и 90% снижение конфликтов "это не моя работа!"
