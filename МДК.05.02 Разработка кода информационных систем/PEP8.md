# **PEP 8: Основные правила (список)**

---

## **1. Отступы**
- Используйте **4 пробела** на уровень отступа
- **Запрещена** табуляция (Tab)
- Продолжение строки должно быть выровнено по смыслу

---

## **2. Длина строки**
- Максимум **79 символов** для кода
- Максимум **72 символа** для комментариев и docstring
- Длинные строки можно разбить с помощью скобок или обратного слэша

---

## **3. Пустые строки**
- **2 пустые строки** между функциями и классами (на верхнем уровне)
- **1 пустая строка** между методами внутри класса
- **1 пустая строка** между логическими блоками кода внутри функции

---

## **4. Пробелы**

### **4.1. Вокруг операторов**
- Пробелы вокруг бинарных операторов: `=`, `+`, `-`, `*`, `/`, `==`, `<`, `>`, `and`, `or`, `in`
- **Нет** пробелов вокруг унарных операторов: `+`, `-`, `~`
- **Нет** пробелов вокруг оператора `**` (степень)

### **4.2. После запятых**
- Пробел **после** запятой, **нет** пробела перед запятой

### **4.3. В скобках**
- **Нет** пробелов сразу внутри скобок: `(1, 2)` а не `( 1, 2 )`

### **4.4. Перед двоеточием в срезе**
- **Нет** пробела перед двоеточием: `lst[:5]` а не `lst[: 5]`

---

## **5. Именование**

| Тип | Стиль | Пример |
|-----|-------|--------|
| Переменные | `snake_case` | `user_name`, `total_count` |
| Функции | `snake_case` | `get_user()`, `calculate_sum()` |
| Классы | `PascalCase` | `UserProfile`, `BankAccount` |
| Константы | `UPPER_SNAKE_CASE` | `MAX_SIZE`, `DEFAULT_COLOR` |
| Приватные атрибуты | `_snake_case` | `_internal_value` |
| Защищённые методы | `_snake_case` | `_validate_data()` |
| "Магические" методы | `__snake_case__` | `__init__`, `__str__` |

---

## **6. Импорты**

- Каждый импорт **на отдельной строке**
- **Нельзя**: `import os, sys, json`
- **Порядок импортов** (с разделением пустыми строками):
  1. Стандартные библиотеки Python
  2. Сторонние библиотеки
  3. Локальные модули
- Импорты в начале файла (после комментариев и docstring)

---

## **7. Кавычки**
- Одинарные и двойные кавычки равнозначны
- Важно **единообразие** во всём проекте
- Для docstring всегда **тройные двойные** кавычки: `"""docstring"""`
- Если в строке есть одинарная кавычка, используйте двойные (и наоборот)

---

## **8. Пробелы в выражениях**

### **✅ Хорошо:**
```python
x = 1
y = x + 5
result = (x + y) * 2
my_list = [1, 2, 3]
my_dict = {'a': 1, 'b': 2}
function(a, b, c)
```

### **❌ Плохо:**
```python
x=1
y=x+5
my_list = [ 1,2,3 ]
function( a , b , c )
```

---

## **9. Запятые и точки с запятой**

- **Нет** точки с запятой в конце строки
- **Нет** нескольких операторов на одной строке
- Завершающая запятая допустима в списках/кортежах (trailing comma)

---

## **10. Комментарии**

### **Блочные комментарии**
- Начинаются с `#` и пробела
- На отдельной строке
- Отступ такой же, как у кода ниже

### **Строчные комментарии**
- Минимум **2 пробела** перед `#`
- Использовать редко (лучше понятное имя переменной)

### **Docstring**
- Тройные двойные кавычки
- Первая строка — краткое описание
- Затем пустая строка и подробное описание (если нужно)

---

## **11. Операторы сравнения с None**

- Использовать `is None` и `is not None`
- **Не использовать** `== None` или `!= None`

---

## **12. Логические операторы**

- Использовать слова `and`, `or`, `not`
- **Не использовать** символы `&&`, `||`, `!`

---

## **13. Исключения**

- Указывать конкретные типы исключений: `except ValueError:`
- **Не использовать** голый `except:`
- Минимальный код внутри `try` (только то, что может вызвать ошибку)

---

## **14. Сравнение булевых значений**

```python
# ✅ Хорошо
if is_valid:
    pass

# ❌ Плохо
if is_valid == True:
    pass

# ✅ Хорошо
if not is_valid:
    pass

# ❌ Плохо
if is_valid == False:
    pass
```

---

## **15. Возврат значений**

- Будьте последовательны: либо всегда возвращайте значение, либо никогда
- Если функция ничего не возвращает, явно напишите `return None`

---

## **16. Доступ к атрибутам**

- Использовать `hasattr()`, `getattr()`, `setattr()` только при необходимости
- Предпочитать прямой доступ: `obj.attribute`

---

## **17. Магические методы**

- Использовать только стандартные (`__init__`, `__str__`, `__len__` и т.д.)
- **Не создавать** свои магические методы

---

## **18. Обратные слэши для переноса строк**

- По возможности использовать скобки вместо `\`
- Если используется `\`, ставить его после оператора, а не перед

---

## **19. Аннотации типов (Type Hints)**

- Пробел после двоеточия: `name: str`
- Пробелы вокруг стрелки: `def func() -> str:`
- Нет пробела перед двоеточием в аннотации

---

## **20. Рекомендуемые инструменты**

| Инструмент | Назначение |
|-----------|------------|
| `flake8` | Проверка PEP 8 |
| `black` | Автоформатирование кода |
| `isort` | Сортировка импортов |
| `pylint` | Глубокий анализ кода |
| `mypy` | Проверка типов |

---

## **Краткая памятка:**

| Правило | Пример ✅ | Пример ❌ |
|---------|-----------|-----------|
| 4 пробела | `def func():␣␣␣␣pass` | `def func():␣␣pass` |
| 79 символов | строка до 79 символов | очень длинная строка, которая не помещается... |
| snake_case | `user_name` | `userName` |
| PascalCase | `UserProfile` | `userProfile` |
| UPPER_CASE | `MAX_SIZE` | `maxSize` |
| пробелы вокруг `=` | `x = 10` | `x=10` |
| пробел после `,` | `[1, 2, 3]` | `[1,2,3]` |
| `is None` | `if x is None` | `if x == None` |
| конкретный except | `except ValueError:` | `except:` |

---

**Запомните:** PEP 8 — это не жёсткие законы, а **рекомендации**. Главное — **единообразие кода** внутри проекта.
