Компоненты React — это **основные строительные блоки** любого приложения на React. Они позволяют разбить интерфейс на независимые, переиспользуемые части и думать о каждой из них в отдельности.

Существует два основных типа компонентов (хотя на практике разница стирается):

1.  **Функциональные компоненты** (современный стандарт).
2.  **Классовые компоненты** (устаревший подход, до React 16.8).

---

### 1. Функциональные компоненты

Это обычные JavaScript-функции. Они принимают объект `props` (свойства) в качестве аргумента и возвращают React-элементы (JSX).

**Самый простой пример:**
```jsx
// 1. Объявление через function
function Welcome(props) {
  return <h1>Привет, {props.name}!</h1>;
}

// 2. Или через стрелочную функцию (более современный синтаксис)
const Welcome = (props) => {
  return <h1>Привет, {props.name}!</h1>;
};
```

С появлением **хуков** (React 16.8) функциональные компоненты стали основным способом написания компонентов, так как они теперь могут управлять состоянием и побочными эффектами (раньше это было доступно только в классах).

---

### 2. Классовые компоненты

Это ES6-классы, которые расширяют `React.Component`. Они обязательно должны содержать метод `render()`, который возвращает JSX.

**Пример:**
```jsx
import React, { Component } from 'react';

class Welcome extends Component {
  render() {
    return <h1>Привет, {this.props.name}!</h1>;
  }
}
```

Сегодня классовые компоненты используются реже, но вы можете встретить их в старых проектах или легаси-коде.

---

### Основные понятия, связанные с компонентами

#### Props (Свойства)
Это входные данные компонента (аргументы функции). Родительский компонент передает данные дочернему через props. Props **нельзя изменять** внутри компонента (они иммутабельны).

```jsx
// Использование компонента (родитель)
<Welcome name="Алиса" />
<Welcome name="Боб" />
```

#### State (Состояние)
Это внутренние данные компонента, которые могут меняться со временем (например, ответ от сервера, открыт ли дропдаун, значение инпута). Когда состояние меняется, компонент перерисовывается (re-render).

В функциональных компонентах для состояния используется хук `useState()`.

```jsx
import React, { useState } from 'react';

function Counter() {
  // Объявляем переменную состояния "count"
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Вы кликнули {count} раз</p>
      <button onClick={() => setCount(count + 1)}>
        Нажми меня
      </button>
    </div>
  );
}
```

### Способы экспорта

Обычно компоненты хранят в отдельных файлах.

**Именованный экспорт:**
```jsx
// Файл Button.jsx
export const Button = () => <button>Click</button>;

// Импорт в другом файле
import { Button } from './Button';
```

**Экспорт по умолчанию (Default export):**
```jsx
// Файл Header.jsx
const Header = () => <header>Logo</header>;
export default Header;

// Импорт
import Header from './Header';
```

### Правила именования
1.  Имена компонентов всегда начинаются с **заглавной буквы** (например, `UserProfile`, `Sidebar`).
2.  Файлы, в которых хранятся компоненты, тоже часто называют с заглавной буквы (`UserProfile.jsx`), но это не строгое правило.

### Типы компонентов по роли (Паттерны)
Хотя технически это все функции, по логике их часто делят на:

1.  **Презентационные (Dumb/Stateless):** Отвечают только за то, *как* выглядит UI. Получают данные через props и отображают их. Обычно не имеют своего состояния (или оно относится только к UI, например, видимость подсказки).
2.  **Контейнеры (Smart/Stateful):** Отвечают за то, *как* работает логика. Содержат бизнес-логику, ходят в API, управляют состоянием и передают данные в презентационные компоненты.
    *С появлением хуков это разделение стало менее строгим, но концептуально оно все еще полезно.*
