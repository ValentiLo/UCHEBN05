# **Практическое занятие №3: Разработка раздела «Введение» документации ИС**

## **Цель занятия:** 
Освоить методику разработки вводного раздела технической документации информационной системы, сформировать навыки структурирования и оформления в соответствии с ГОСТ и отраслевыми стандартами.

**Продолжительность:** 2 академических часа (90 минут)

## **Теоретическая часть (15 минут)**

### **1. Назначение раздела «Введение»**

**Основные цели:**
- Обоснование необходимости создания/развития ИС
- Определение целей и задач системы
- Описание предметной области
- Установление границ проекта
- Определение целевой аудитории документа

### **2. Структура раздела «Введение» по ГОСТ 34.201-89**

| Подраздел | Содержание | Объем |
|-----------|------------|-------|
| **1.1 Наименование программы** | Полное и сокращенное название | 1-2 строки |
| **1.2 Основание для разработки** | Нормативные документы, приказы | 0,5-1 стр. |
| **1.3 Наименование организаций** | Заказчик, разработчик, исполнители | 0,5 стр. |
| **1.4 Назначение и цели создания** | Что решает система, бизнес-цели | 1-2 стр. |
| **1.5 Краткая характеристика области применения** | Сфера использования, пользователи | 1 стр. |
| **1.6 Стадии и этапы разработки** | План работ, сроки | 0,5-1 стр. |
| **1.7 Порядок оформления и предъявления** | Правила приемки, документы | 0,5 стр. |

### **3. Особенности для разных типов документации**

**Оперативная документация:**
- Акцент на текущем состоянии системы
- Описание архитектуры и компонентов
- Инструкции для администраторов

**Проектная документация:**
- Техническое задание (ТЗ)
- Технический проект (ТП)
- Рабочая документация (РД)

**Пользовательская документация:**
- Руководство пользователя
- Справочная система
- Быстрый старт

```markdown
# 1. ВВЕДЕНИЕ

## 1.1 Общие сведения
Система учета товаров на складе нужна для того, чтобы учитывать товары.

## 1.2 Цели
Цель - сделать учет товаров.

## 1.3 Задачи
- Учитывать товары
- Печатать документы
- Работать быстро

## 1.4 Пользователи
Будут пользоваться кладовщики и другие.

## 1.5 Сроки
Система будет готова когда сделаем.
```

**Задание:** Найдите ошибки и предложите улучшенную версию.

**Анализ ошибок:**
1. **Неформальный стиль** – использование разговорных выражений
2. **Отсутствие конкретики** – нет цифр, показателей
3. **Неполная структура** – отсутствуют обязательные разделы
4. **Неопределенные формулировки** – "другие", "когда сделаем"
5. **Отсутствие обоснования** – почему система нужна

## **Критерии оценки (15 минут)**

### **Критерии оценки раздела «Введение»:**

| Критерий | Максимальный балл | Описание |
|----------|-------------------|----------|
| **Полнота структуры** | 25 | Все обязательные подразделы присутствуют |
| **Качество формулировок** | 20 | Точные, конкретные, профессиональные формулировки |
| **Обоснованность** | 20 | Есть цифры, показатели, аналитика |
| **Соответствие стандартам** | 15 | Соответствие ГОСТ/отраслевым стандартам |
| **Практическая значимость** | 10 | Реальные, достижимые цели |
| **Оформление** | 10 | Структурированность, читаемость, единый стиль |
| **Итого** | **100** | |

### **Шкала перевода в оценку:**
- **85-100 баллов:** Отлично (5)
- **70-84 балла:** Хорошо (4)
- **50-69 баллов:** Удовлетворительно (3)
- **Менее 50 баллов:** Неудовлетворительно (2)

### **Типичные ошибки и как их избежать:**

| Ошибка | Как исправить | Пример |
|--------|---------------|--------|
| **Расплывчатые формулировки** | Использовать SMART-критерии | Вместо "улучшить учет" → "сократить время обработки документа с 2 часов до 30 минут" |
| **Отсутствие цифр** | Добавить KPI | "Увеличить скорость работы на 30%" |
| **Неполная структура** | Использовать чек-лист | Проверить по ГОСТ 34.201-89 |
| **Неуместный стиль** | Придерживаться технического стиля | Избегать разговорных выражений |
| **Отсутствие обоснования** | Добавить анализ проблемы | "В связи с ростом количества клиентов на 40% за год..." |

### **Пример SMART-целей для раздела:**

**Плохо:** "Сделать систему удобной"
**Хорошо (SMART):**
- **S**pecific (Конкретная): "Сократить количество кликов для создания заказа с 7 до 3"
- **M**easurable (Измеримая): "Увеличить скорость обработки запроса на 25%"
- **A**chievable (Достижимая): "Снизить количество ошибок при вводе данных на 90%"
- **R**elevant (Релевантная): "Соответствует бизнес-процессам компании"
- **T**ime-bound (Ограниченная по времени): "Достичь цели к 30.06.2024"
