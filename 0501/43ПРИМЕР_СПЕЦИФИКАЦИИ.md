## 📌 **1. ВВЕДЕНИЕ**

### **1.1. Назначение документа**

Настоящий документ определяет функциональные и нефункциональные требования к системе управления задачами «TaskMaster» (далее — Система). Документ предназначен для заказчика, разработчиков, тестировщиков и технических писателей. Он является основой для проектирования, разработки, тестирования и приемки продукта.

### **1.2. Область применения**

Система «TaskMaster» предназначена для малых команд разработчиков (3-15 человек) и решает следующие задачи:
- Централизованное управление задачами проекта
- Контроль сроков выполнения
- Распределение ответственности между исполнителями
- Повышение прозрачности рабочего процесса

**Ожидаемые преимущества:**
- Сокращение времени на координацию задач на 30%
- Уменьшение количества просроченных задач на 50%
- Повышение прозрачности распределения нагрузки

### **1.3. Определения, термины и сокращения**

| Термин | Определение |
|--------|-------------|
| **SRS** | Software Requirements Specification — спецификация требований к ПО |
| **Задача** | Единица работы, имеющая название, описание, срок, исполнителя и статус |
| **Проект** | Совокупность задач, объединенных общей целью |
| **Исполнитель** | Пользователь, назначенный ответственным за выполнение задачи |
| **Наблюдатель** | Пользователь, получающий уведомления о изменениях задачи |
| **Доска** | Визуальное представление задач в виде колонок (канбан-доска) |

## 🏗️ **2. ОБЩЕЕ ОПИСАНИЕ**

### **2.1. Видение продукта**

**Рисунок 1. Контекстная диаграмма Системы**

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   Пользователь  │────▶│    TaskMaster   │────▶│     Telegram    │
│   (Web-клиент)  │◀────│   (Серверная    │◀────│  Bot API        │
└─────────────────┘     │     часть)      │     └─────────────────┘
         │               └────────┬────────┘            │
         │                        │                     │
         ▼                        ▼                     ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   Браузер       │     │   PostgreSQL    │     │   SMTP-сервер   │
│   (Chrome,      │     │   (БД)          │     │   (Email)       │
│   Firefox)      │     └─────────────────┘     └─────────────────┘
└─────────────────┘
```

Система является самостоятельным веб-приложением, взаимодействующим с СУБД PostgreSQL для хранения данных, с Telegram Bot API для отправки уведомлений и со SMTP-сервером для email-рассылок.

### **2.2. Функциональность продукта**

Основные функции Системы:
1. Управление пользователями и проектами
2. Создание и редактирование задач
3. Назначение исполнителей и наблюдателей
4. Отслеживание сроков выполнения
5. Отправка уведомлений (email/Telegram)
6. Формирование отчетов по задачам
7. Визуализация задач на канбан-доске

### **2.3. Классы и характеристики пользователей**

| Класс | Описание | Потребности | Привилегии |
|-------|----------|-------------|------------|
| **Анонимный пользователь** | Неавторизованный посетитель | Просмотр информации о системе, регистрация | Только просмотр публичной информации |
| **Обычный пользователь** | Сотрудник, участник команд | Создание/редактирование своих задач, просмотр задач команды | CRUD своих задач, чтение всех задач проекта |
| **Руководитель проекта (PM)** | Управляет проектом | Назначение исполнителей, контроль сроков, формирование отчетов | Полный доступ к задачам проекта |
| **Администратор** | Технический специалист | Управление пользователями, настройка системы | Все права + управление учетными записями |

### **2.4. Операционная среда**

| Компонент | Требования |
|-----------|------------|
| **Сервер** | Linux (Ubuntu 20.04+), 2+ vCPU, 4+ GB RAM |
| **Клиент** | Браузер: Chrome 90+, Firefox 88+, Edge 90+, Safari 14+ |
| **СУБД** | PostgreSQL 13+ |
| **Сторонние сервисы** | Telegram Bot API, SMTP-сервер (для email) |

### **2.5. Ограничения дизайна и реализации**

- **Язык программирования:** Python 3.10+ (бэкенд), JavaScript (фронтенд)
- **Фреймворк:** Flask 2.0+ (бэкенд), React 18+ (фронтенд)
- **База данных:** PostgreSQL через SQLAlchemy ORM
- **Стиль кода:** PEP 8 для Python, Airbnb JavaScript Style Guide
- **Безопасность:** Все пароли хэшируются (bcrypt), HTTPS обязательно
- **Архитектура:** REST API + клиентское SPA

### **2.6. Допущения и зависимости**

**Допущения:**
- Пользователи имеют доступ к интернету (минимальная скорость 1 Мбит/с)
- Пользователи владеют базовыми навыками работы с веб-браузером
- В организации настроена корпоративная почта для уведомлений

**Зависимости:**
- Наличие Telegram у пользователей для получения уведомлений (опционально)
- Доступность сервера PostgreSQL
- Стабильная работа Telegram Bot API

### **4.3. Требования к целостности, хранению и утилизации данных**

- **Целостность:** Каскадное удаление задач при удалении проекта
- **Хранение:** Данные хранятся в зашифрованном виде на диске
- **Резервное копирование:** Ежедневное полное копирование БД
- **Утилизация:** Удаленные проекты хранятся 30 дней в архиве, затем удаляются безвозвратно

## 🖥️ **5. ТРЕБОВАНИЯ К ВНЕШНИМ ИНТЕРФЕЙСАМ**

### **5.1. Пользовательские интерфейсы**

- Интерфейс должен быть адаптивным (mobile-first)
- Все элементы управления должны быть доступны с клавиатуры

### **5.2. Программные интерфейсы**

- REST API с JSON-форматом данных
- Документация API через Swagger (доступна по `/api/docs`)
- Telegram Bot API для отправки уведомлений
- SMTP для отправки email

### **5.3. Коммуникационные интерфейсы**

- HTTPS (TLS 1.2+) для всех соединений
- WebSocket для обновлений канбан-доски в реальном времени
