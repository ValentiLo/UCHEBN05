Отвечу прямо: **это верное начало, но недостаточно для рабочей системы**. 

У вас есть основные сущности, но пропущены **критические таблицы** (категории, поставки, возвраты, скидки) и **неправильно спроектированы связи** (особенно для одежды). 

Ниже покажу **правильную ER-диаграмму** для магазина одежды с объяснением, почему ваша схема не взлетит и как её исправить.

## ❌ Что не так в вашей схеме

| Проблема | Почему это плохо |
| :--- | :--- |
| **Нет таблицы "Товарные варианты" (SKU)** | Одежда продаётся в размерах и цветах. Нельзя хранить остатки для "футболки" — нужно для "футболка, размер M, цвет чёрный". |
| **"Размер и цвет" — это одна таблица?** | Это атрибуты варианта, а не отдельная таблица. Иначе получится дублирование (каждый цвет × каждый размер = комбинаторный взрыв). |
| **Нет категорий и брендов** | Без них каталог нельзя структурировать, а поиск по категориям — основа UX. |
| **Нет истории цен** | Цена меняется (скидки, распродажи). Если хранить цену только в "Продукте", вы потеряете историю. |
| **Нет возвратов** | Это часть бизнеса одежды (примерка, брак). Возврат влияет на остатки и финансы. |
| **"Продажи" и "Товар в продаже"** — это правильно (заказ + позиции), но нет статусов заказа | Нужны этапы: "создан → оплачен → собран → отправлен → доставлен → возвращён". |

## ✅ Правильная структура БД (PostgreSQL)

Ниже — **минимальный рабочий набор таблиц** (15 таблиц вместо 6). 

### 1. Справочники (каталог)

```sql
-- Категории (дерево: Одежда → Верхняя → Куртки → Пуховики)
CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    parent_id INT REFERENCES categories(id) ON DELETE CASCADE,
    slug VARCHAR(100) UNIQUE NOT NULL
);

-- Бренды
CREATE TABLE brands (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) UNIQUE NOT NULL
);

-- Товары (общая информация)
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    brand_id INT REFERENCES brands(id),
    category_id INT REFERENCES categories(id),
    gender VARCHAR(10) CHECK (gender IN ('male', 'female', 'unisex')),
    season VARCHAR(20), -- 'spring/summer 2026'
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 2. **Главная фишка — Товарные варианты (SKU)**

```sql
-- Таблица размеров (глобальный справочник)
CREATE TABLE sizes (
    id SERIAL PRIMARY KEY,
    name VARCHAR(10) UNIQUE NOT NULL -- 'XS', 'S', 'M', 'L', 'XL', '42', '44'...
);

-- Таблица цветов
CREATE TABLE colors (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) UNIQUE NOT NULL, -- 'Black', 'White', 'Red'
    hex_code CHAR(7) -- '#000000'
);

-- Варианты товара (каждая комбинация товар+размер+цвет = отдельный SKU)
CREATE TABLE product_variants (
    id SERIAL PRIMARY KEY,
    product_id INT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
    size_id INT REFERENCES sizes(id),
    color_id INT REFERENCES colors(id),
    sku VARCHAR(50) UNIQUE NOT NULL, -- 'TSHIRT-BLK-M-01'
    price DECIMAL(10,2) NOT NULL,    -- актуальная цена (можно вынести в отдельную таблицу истории)
    old_price DECIMAL(10,2),         -- для отображения скидки
    weight_kg DECIMAL(5,2),
    is_active BOOLEAN DEFAULT true,
    UNIQUE(product_id, size_id, color_id) -- защита от дублей
);
```

### 3. Склад (остатки и движения)

```sql
-- Остатки (текущие)
CREATE TABLE stock (
    variant_id INT PRIMARY KEY REFERENCES product_variants(id) ON DELETE CASCADE,
    quantity INT NOT NULL DEFAULT 0 CHECK (quantity >= 0),
    reserved INT NOT NULL DEFAULT 0,  -- зарезервировано в незавершённых заказах
    available INT GENERATED ALWAYS AS (quantity - reserved) STORED,
    updated_at TIMESTAMP DEFAULT NOW()
);

-- История поступлений на склад
CREATE TABLE stock_movements (
    id SERIAL PRIMARY KEY,
    variant_id INT REFERENCES product_variants(id),
    quantity INT NOT NULL, -- положительное = приход, отрицательное = списание
    type VARCHAR(20) NOT NULL CHECK (type IN ('receipt', 'write_off', 'return', 'adjustment')),
    reason TEXT, -- 'Поставка №123', 'Инвентаризация', 'Возврат от клиента'
    created_at TIMESTAMP DEFAULT NOW(),
    user_id INT REFERENCES users(id) -- кто выполнил
);
```

### 4. Клиенты и заказы

```sql
-- Пользователи (клиенты + сотрудники)
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(100) UNIQUE NOT NULL,
    phone VARCHAR(20),
    password_hash VARCHAR(255) NOT NULL,
    full_name VARCHAR(150),
    role VARCHAR(20) DEFAULT 'client' CHECK (role IN ('client', 'manager', 'admin', 'warehouse')),
    bonus_points INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Заказы (продажи)
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    user_id INT REFERENCES users(id) ON DELETE SET NULL,
    order_number VARCHAR(20) UNIQUE NOT NULL,
    status VARCHAR(30) NOT NULL DEFAULT 'new' 
        CHECK (status IN ('new', 'paid', 'assembling', 'shipped', 'delivered', 'cancelled', 'returned')),
    total_amount DECIMAL(10,2) NOT NULL,
    discount_amount DECIMAL(10,2) DEFAULT 0,
    payment_method VARCHAR(30), -- 'card', 'cash', 'bonus'
    payment_status VARCHAR(20) DEFAULT 'pending' CHECK (payment_status IN ('pending', 'paid', 'failed', 'refunded')),
    shipping_address TEXT,
    tracking_number VARCHAR(100),
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Позиции в заказе
CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    order_id INT REFERENCES orders(id) ON DELETE CASCADE,
    variant_id INT REFERENCES product_variants(id),
    quantity INT NOT NULL CHECK (quantity > 0),
    price_per_unit DECIMAL(10,2) NOT NULL, -- фиксируем цену на момент покупки
    total_price DECIMAL(10,2) GENERATED ALWAYS AS (price_per_unit * quantity) STORED
);
```

### 5. Возвраты (важная специфика для одежды)

```sql
CREATE TABLE returns (
    id SERIAL PRIMARY KEY,
    order_id INT REFERENCES orders(id),
    user_id INT REFERENCES users(id),
    order_item_id INT REFERENCES order_items(id),
    quantity INT NOT NULL,
    reason VARCHAR(100), -- 'wrong size', 'defect', 'does not fit'
    status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending', 'approved', 'rejected', 'completed')),
    refund_amount DECIMAL(10,2),
    created_at TIMESTAMP DEFAULT NOW(),
    processed_at TIMESTAMP
);
```

### 6. Для отчётов и аналитики

```sql
-- История изменения цен (для аналитики)
CREATE TABLE price_history (
    id SERIAL PRIMARY KEY,
    variant_id INT REFERENCES product_variants(id),
    old_price DECIMAL(10,2),
    new_price DECIMAL(10,2),
    changed_at TIMESTAMP DEFAULT NOW(),
    reason VARCHAR(50) -- 'sale', 'manual', 'seasonal'
);
```

## 🔗 Связи между таблицами (главное)

```
categories (1) ───┬── (N) products
brands (1) ───────┴── (N) products
                  │
products (1) ──── (N) product_variants
sizes (1) ────────┘
colors (1) ───────┘
                  │
product_variants (1) ─── (N) order_items
product_variants (1) ─── (1) stock
product_variants (1) ─── (N) stock_movements
                  │
orders (1) ───── (N) order_items
users (1) ────── (N) orders
users (1) ────── (N) returns (как клиент)
orders (1) ───── (N) returns
```

## 📊 Визуализация (как будет выглядеть в реальности)

Если вы добавите в каталог **"Куртка зимняя"**, в БД появится:
- 1 запись в `products`
- 4 записи в `product_variants` (S/чёрный, M/чёрный, S/синий, M/синий)  
- 4 записи в `stock` (по 10 штук каждого)  
- При заказе 1 куртки M/чёрный — создаётся `order_item`, и в `stock` уменьшается `reserved` на 1
